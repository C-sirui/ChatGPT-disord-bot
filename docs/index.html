    What a request goes through

    Every call from an editor follows this path. The highlighted steps are where money and capacity get reserved and settled.

    Built in Phase 1

    • OpenAI-compatible /v1/chat/completions (streaming) and /v1/models
    • Buyer accounts, relay keys, prepaid balance, Stripe Checkout + signed webhooks
    • Seller keys encrypted at rest, hourly token budgets, concurrency caps, earnings, payout requests
    • Double-entry ledger with holds and a reconcile check
    • Failover, circuit breakers, per-provider resale gate
    • Postgres, migrations, Docker, CI, health and metrics endpoints

    Dev build

    • One command: SQLite, built-in fake provider, seeded buyer, seller and admin accounts
    • Per-request timeline in a header, the logs and /debug/requests/:id
    • /debug/config shows each setting's source with secrets hidden
    • Fault injection: x-mock-fault: 429 | 500 | 401 | hang | drop | no-usage

    Try it locally

    cd token-relay && npm install && npm run dev

curl -s localhost:8787/v1/chat/completions \
  -H 'authorization: Bearer trk_dev_buyer_0000000000000000000000000000000' \
  -H 'content-type: application/json' \
  -d '{"model":"mock-fast","stream":true,"messages":[{"role":"user","content":"hello"}]}'

    Editor setup: base URL http://localhost:8787/v1, the key above, model mock-fast.
